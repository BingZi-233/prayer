# 性能与可维护性第一阶段设计

## 目标

在不改变客服业务语义和现有 HTTP 响应兼容字段的前提下，减少管理后台高频请求的数据库开销，消除 API 数据装配重复，并让排行榜等读路径的成本随数据量更平稳地增长。

## 当前证据

- API 路由重复创建 `Repo` 并重复解析配置；同一进程的 SQLite 连接虽然按路径复用，但仓储级预编译语句缓存没有跨请求复用。
- `question_topics ORDER BY updated_at`、人工会话超时筛选和开放工单排序在现有数据库上分别出现全表扫描或临时排序。
- 排行榜对每个主题单独查询样例，并对前 30 个主题串行执行 embedding。
- 后台页面存在全局状态轮询与页面轮询叠加；会话页另有未设 in-flight 闸门的定时轮询。

## 方案

### 统一应用数据上下文

新增应用级上下文模块，统一提供：

- `configRepo`：读取和写入配置种子的仓储，路径来自 `DB_PATH`；
- `cfg`：通过现有 `getConfig` 解析、迁移和校验后的 `AppConfig`；
- `repo`：指向 `cfg.dbPath` 的业务仓储。

`lib/db/shared.ts` 增加按路径复用 `Repo` 的入口，使 `SqliteContext` 的语句缓存跨 API 请求复用。配置路由仍明确使用 `configRepo`，避免把可变业务数据库误当成配置存储。

### 读侧索引和批量查询

新增一个只包含结构变更的 SQLite 迁移版本，建立主题更新时间、人工会话筛选、工单状态排序和主题样例时间的索引。迁移必须可重复执行，失败时由现有迁移事务回滚。

主题仓储新增批量样例查询：一次 SQL 返回多个主题各自限定数量的去重样例，保留现有按最近时间排序的结果语义。

### 排行榜成本控制

排行榜继续返回现有字段和窗口口径；改为批量取样，并以固定并发度评估前 N 个主题的知识库覆盖，避免串行 embedding。对异常或空样例保留现有回退行为。为并发辅助函数和路由边界增加测试。

### 管理后台轮询

会话列表轮询改用已有的 in-flight/退避/隐藏页保护逻辑，不改变深链、筛选和当前会话刷新语义。全局 LiveProvider 的 context value 采用稳定引用，减少无关状态更新造成的消费方重渲染。

## 非目标

本阶段不改动：

- poller 的取消/等待和 Runtime 重配置生命周期；
- 配置并发写入回滚策略；
- 知识库文件与 SQLite 的跨介质原子性；
- 大页面拆分、认证模型和 Cloud 多租户架构；
- 客服提示词、模型参数和数据库业务字段语义。

## 验收标准

1. 现有测试行为保持不变，新增测试覆盖上下文装配、索引迁移、批量样例和排行榜并发边界。
2. `EXPLAIN QUERY PLAN` 对新增索引的目标查询不再使用临时排序或无谓全表扫描。
3. 排行榜的数据库样例查询次数不随主题数线性增加；embedding 并发不超过设定上限。
4. 会话页慢请求时同时在途的列表请求最多为一个，页面切换和深链行为保持不变。
5. 通过 `pnpm check` 与隔离生产构建，且不把 `data/`、凭证或运行时产物纳入提交。
